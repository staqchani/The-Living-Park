# The Living Park project instructions

Read docs/MASTER_SPEC.md, docs/IMPLEMENTATION_TRACKER.md, docs/ARCHITECTURE.md and the latest entry in docs/DEVELOPMENT_LOG.md at session start. Re-read the relevant specification before changing a dependent system. The master specification is the original source and must be preserved. Record interpretations and newly authorized changes separately.

- Work one milestone at a time. Verify its acceptance criteria before advancing. Add evidence and update relevant tracker rows with each meaningful change. Record blockers, their impact and exact unblock steps, then continue independent work in scope.
- At session end, record decisions, actual commands and results, affected files, blockers and the next action. Commit verified milestones when a repository is available. Inspect staged changes and exclude unrelated user work. Keep builds, caches and local credentials out of Git.
- The mobile project at E:\Projects\Roller Coaster Mobile is read-only. Never open it in Unity for this project, run a reimport, or write, rename, delete or overwrite anything there. All experiments belong in the independent VR project or disposable scratch.
- Copy only audited assets with proven reuse rights. Preserve necessary .meta files and GUIDs, check collisions and dependency closure, record every import, and exclude unrelated scripts, SDKs, ads, analytics and packages. Build an original replacement when reuse rights cannot be established.
- Use maintainable C# with explicit composition, cohesive components, and dependency boundaries. Keep simulation authoritative and independent of XR input, cameras, MonoBehaviour views, storage and frame timing. Use ScriptableObjects as immutable authored definitions and stable IDs for runtime records and saves.
- Validate commands centrally. Make placement, payments and rewards atomic and resistant to repeated requests. Use integer minor units for money, versioned saves, safe temporary writes, backups and round-trip tests. Keep public contracts narrow. Avoid scene searches in update loops, monolithic managers, duplicate logic and excessive global state.
- Preserve controller-first comfort. Default to teleportation and snap turning. Maintain tracked head movement at all times and implement safe boarding, unloading and comfort exits. Keep the first release offline. Add networking only when separately scoped under the specification.
- Keep .blend sources and Blender Python outside Assets. Import only runtime exports. Verify shaders, textures, animation, collisions and performance on the intended runtime. Use bounded AI updates, pooling and measurable Quest budgets.
- Distinguish static checks, editor tests, Android builds and headset testing. Report the exact executed checks and outcomes. Claim Quest hardware verification only for a test actually run on a Quest device.
